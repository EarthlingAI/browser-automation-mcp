# CLAUDE.md (browser-automation-mcp)

Cross-tab Chrome control via a passive MV3 extension. 29 tools that drive the user's real authenticated browser in the background — without raising the window or stealing focus, except the one explicit opt-in escape hatch `browser_activate_tab(level:"foreground")`. 51 invariants govern the design — see "Key Invariants" below.

Update this file when conventions or design principles change. Update `README.md` when the codebase changes (new tools, parameters, files). See `README.md` for tools, parameters, architecture, and setup.

## Design Principles

### Site-agnostic by construction

Every capability here is a **general browser primitive** — never a special-case for one site, product, or DOM shape. Real-world gaps surface on specific pages (an LMS course player, a SCORM dispatch frame, a signature-pad canvas), but the fix must generalise the gap to its whole *class* before any code is written: "this Storyline course lives in a same-origin iframe" becomes "descend same-origin iframes"; "this Vimeo play button needs a real gesture" becomes "trusted coordinate input"; "this UI5 button hides in a shadow root" becomes "descend open shadow roots". Concretely:

- **No site/product/vendor names** in code, comments, tool descriptions, or schema `.describe(...)` strings. The same bundle ships fleet-wide and standalone — a name leaking in is a bug.
- **No DOM-shape special-casing** keyed to one framework's class names or attributes. Heuristics key on *semantic* signals (role, shadow-root presence, frame origin, draggability), never on `class*="sc-"` or a vendor's `data-*`.
- **Generalise before implementing.** When a real page breaks, identify the browser capability it exercises and build that capability for all pages. The breaking page becomes a live regression case, not the design target.

### Agent-First Tool Design

This server is consumed by AI agents, not humans. Every design decision flows from that:

- **Optimal defaults for zero-config usage.** Action tools auto-snapshot (`snapshot=true`) and auto-settle (`wait_for_settle="dom"`) so the agent can do `snapshot()` → `click(ref:"5")` with no flags. Screenshots default to JPEG quality 70 so the typical capture stays well inside the token budget.
- **Observe-act loop as the core abstraction.** `browser_snapshot` returns a pruned, numbered a11y tree. Action tools consume `ref` IDs from that snapshot and auto-refresh it afterwards. The agent never manages tree state manually.
- **Settle protocol kills the same-tick double-fire.** An action returns only after the page has shown a state delta — DOM mutation, network request, or named selector. The agent's `wait_for_settle` arg picks the signal. This is what stops the "click looked like a no-op so I fired it again" failure mode.
- **Self-explanatory schemas.** Zod `.describe(...)` strings are the primary documentation agents see. If an agent has to read the README to use a tool correctly, the descriptions have failed.
- **Errors that guide recovery.** Extension-disconnect errors carry an actionable manual-reload hint. Stale-ref errors name nearby refs and tell the agent to re-snapshot. Lease-required errors quote the exact next call to make.
- **Background by default.** Tab creation uses `chrome.tabs.create({active:false})`. Screenshots use `chrome.debugger Page.captureScreenshot`. Focus is never stolen from the user — with one explicit, opt-in exception: `browser_activate_tab(level:"foreground")` (reserved for OS file pickers / clipboard / drag-drop / native `:focus` UI). `browser_activate_tab(level:"render")` (CDP focus-emulation) resumes faithful rendering of a backgrounded canvas tab without any window raise.

## Architecture

```
browser-automation-mcp/
├── src/
│   ├── index.ts           # Entry — dispatches --daemon vs bridge mode
│   ├── protocol.ts        # Wire types shared by daemon, bridge, extension (incl. snapshot_capture + annotate_image ExtCommand kinds)
│   ├── daemon/            # Singleton daemon — owns leases, brokers daemon↔extension WS
│   ├── bridge/            # One-per-agent MCP server (stdio or streamable-HTTP)
│   │   └── tools/         # One file per tool group (tabs / observe / interact) + shared modules (capture / save / visual / containment / coerce)
│   └── snapshot/          # A11y tree pruner
├── browser-extension/     # Unpacked MV3 extension — service worker + in-page helpers (also: OffscreenCanvas annotate handler)
└── scripts/               # Build (esbuild) + tests (node --test)
```

`bridge/registry.ts` is the single chokepoint where tool registration, the per-session ref registry, the settle policy, the lean-JSON envelope (text + optional native MCP image block), and the per-tab `environment` stamping (#43) all live — new tools never reach for `server.registerTool` directly. `bridge/tools/capture.ts::runUnifiedCapture` is the single source of truth for every "look at the page" call — shared by `browser_snapshot` and the auto-snapshot replay path — and emits a two-hop sequence (`snapshot_capture` atomic tree+screenshot, then optional `annotate_image` OffscreenCanvas overlay). The daemon outlives bridges, so lease state survives bridge respawn. The MV3 service worker is wiped on every extension reload — its per-tab Maps come back empty and are rebuilt from `chrome.tabs.query` on each fresh WS connect, pushed daemon-ward via the initial `tab_updated` flurry.

## Conventions

- **2-space indentation** for TypeScript and JavaScript. Intentionally different from windows-native-mcp's tabs — this codebase predates the unification, and a mid-stream reformat would obscure every phase's review history.
- **TypeScript strict mode** — `tsc --noEmit` is part of every build.
- **Zod for schemas.** Use `.describe(...)` only when the parameter name + type aren't self-explanatory. Apply `z.coerce.number()` for numerics, `z.preprocess(coerceToArray, ...)` for arrays, `z.preprocess(coerceBoolean, z.boolean())` for booleans. `z.coerce.boolean()` is forbidden — it truthy-coerces any non-empty string.
- **Modern `server.registerTool` API** — never `server.tool()` (deprecated) or `setRequestHandler(ListToolsRequestSchema)` (raw).
- **All 4 annotations explicit on every tool.** No defaults. Read-only tools must declare `readOnlyHint: true` (planning-phase agent runtimes gate on it).
- **Errors carry structured fields** (`leasedBy`, `since`, `hint`, `recovery`, `kind`) through the daemon → bridge → envelope pipeline. `toolError` strips null/undefined keys cleanly.
- **`console.error` for all logging** — stdout is the MCP protocol stream in stdio mode.
- **No new runtime dependencies.** The bundle dep set is `@modelcontextprotocol/sdk` + `ws` + `zod` + `zod-to-json-schema`. Tests use Node's built-in `--test`. Screenshot resize uses MV3 `OffscreenCanvas` + `createImageBitmap` (no `sharp`).
- **One file per tool group** in `src/bridge/tools/` (tabs / observe / interact). Shared schema helpers live in `coerce.ts`.
- **`helpers.js` is versioned** — bump `HELPERS_VERSION` when changing the in-page contract (new act kind, return-shape change). Re-injection becomes a no-op so the page-side `nodeMap` survives action sequences.
- **Tests live in `scripts/tests/`** (pure-function `node --test` harness) and `scripts/harness/` (fixture/baseline replay through the pruner). There is no parallel top-level `tests/` folder — extend these two. Page-side helper behaviour (frame/shadow descent) is validated through the harness fixtures; bridge wiring through `scripts/tests/`.

## Adding a New Tool

1. Add the wire type to `src/protocol.ts` under `ExtCommand` (if the daemon → extension hop is new).
2. Implement the in-page side in `browser-extension/inject/helpers.js` (if it touches the DOM) or the service-worker side in `browser-extension/background.js` (if it's a `chrome.*` glue call). Bump `HELPERS_VERSION` if you changed the in-page contract.
3. Wire the dispatch case in `background.js::dispatchInner`.
4. If your tool mutates the page, add its kind to `ACTION_KINDS` in `background.js` (drives the "acting" indicator) and `SETTLE_KINDS` (drives the settle observer).
5. Register the bridge-side tool in the appropriate `src/bridge/tools/*.ts` file via `registerTool` (read-only) or `registerActionTool` (auto-snapshot + auto-settle wrapper). Both helpers require `title`, `description`, `annotations` (all 4 hints), `schema` (zod), and `handler`. If the tool returns a screenshot, return the `CaptureResult` shape `{payload, image?}` (or call `runUnifiedCapture` directly) — both wrappers auto-detect this shape and emit a mixed image+text MCP content array.
6. Apply the coerce sweep — every numeric/boolean/array param needs `z.coerce.*` or `z.preprocess(...)` (see Conventions).
7. Add the tool's expected annotation policy to `scripts/tests/annotations.test.mjs`'s `EXPECTED` table. This is the sweep test that prevents annotation drift.
8. Update `README.md` — tool table + the full file tree if you added a file.

## Key Invariants

These must remain true across all changes:

1. **Never activate a tab — except the two sanctioned sites.** `chrome.tabs.create` always passes `active:!background` (default `background=true`). `chrome.tabs.update({active:true})` appears in exactly TWO places in `background.js`: (a) `bringToFront` — the explicit opt-in focus-steal that `browser_activate_tab(level:"foreground")` routes to (invariant #29), the only ACQUISITIVE activation; (b) the popup focus-restore net in `tabs.onCreated` (invariant #46) — RESTORATIVE only: it re-activates the tab the user was on before a leased tab's popup stole focus, never acquires focus the user didn't already have. Forbidden everywhere else.
2. **Never raise the browser window — except `browser_activate_tab(level:"foreground")`.** Screenshots use `chrome.debugger Page.captureScreenshot`. `chrome.tabs.captureVisibleTab` is forbidden — it forces the tab active. `chrome.windows.update({focused:true})` appears in exactly ONE place: `bringToFront` (invariant #29). `browser_activate_tab(level:"render")` resumes rendering via CDP focus-emulation and never raises the window.
3. **Daemon is singleton, race-safe.** First bridge that finds the port unbound spawns it via `daemon.lock`. Concurrent bridges that observe daemon death simultaneously race-share the next spawn; exactly one new daemon results.
4. **Daemon's WebSocket is Origin-gated.** The only accepted Origin is `chrome-extension://<BROWSER_EXTENSION_ID>` (CRX `key` in `manifest.json` pins the ID). No user-visible token paste required.
5. **Lease state is per-daemon-process and lost on respawn.** Bridges recover transparently: the next action returns `lease_required` and the agent re-claims via `browser_switch_tab`.
6. **All action tools auto-snapshot by default** (`snapshot=true`). Override only when chaining many actions back-to-back to save round-trips.
7. **All action tools auto-settle by default** (`wait_for_settle="dom"`, `settle_timeout=1500`). Same-tick re-fires return only after the page has shown a delta or after 1.5s, whichever fires first.
8. **Auto-snapshot replays `detail`, `limit`, `viewportOnly`, `tabId`, `screenshot`, `quality`, `maxWidth`, `includeCrossOriginFrames` from the last explicit `browser_snapshot` call.** Agents that snapshotted full-mode stay in full-mode on auto-refresh; agents that opted into `screenshot:"annotated"` or `screenshot:"raw"` keep getting the same flavour of image per action until they explicitly set `screenshot:"off"`. `screenshot` is tri-state (Round 10): `"off"` (default, tree only) / `"annotated"` (tree + ref-badged image) / `"raw"` (tree + clean pixels). `save_to_path`, `save_tree_to_path`, and `scope` are NEVER replayed — saving is a per-call opt-in and scoping a per-call drill-down, never session modes (#39; avoids silent disk fill-up and permanently-narrowed auto-snapshots over long sessions). `format` is NOT replayed because it's not a session-mode field — it's derived from `save_to_path`'s extension on each call (defaults to JPEG).
9. **All 4 tool annotation hints are declared explicitly.** Read-only tools must declare `readOnlyHint:true` (planning-phase agent runtimes gate on it); write tools must never claim it. The full policy table lives in `scripts/tests/annotations.test.mjs` and is sweep-tested on every CI run.
10. **Refs are stable + non-evicting; the per-session registry validates them.** Page-side, a given element keeps ONE id across every walk — a persistent `WeakMap<Element,id>` in `helpers.js`, never reset on `__mcpA11y()`; the reverse `id→element` map holds `WeakRef`s (gated on `el.isConnected`) so detached/replaced nodes stay garbage-collectable. Bridge-side, `populateRefs` MERGES each snapshot into a cumulative `refRegistry` (reset only when the snapshot tab changes — page-side ids are per-tab), while `lastSnapshotRefs` keeps just the latest snapshot (the fast-path "definitely current" set + the annotation hop's rect source). `execOnLeasedTab` calls `resolveRef` BEFORE the action hop: an unknown (never-minted) ref fails fast with a nearby-refs error; a known ref that isn't freshly-current (`refNeedsVerification` is true — carried forward from an earlier snapshot, or any ref after an action flips `isStale=true`) is confirmed live via a read-only `resolve_ref` probe, so a since-removed element errors with a "no longer exists" nearby-refs message instead of firing a silent no-op. A ref resolves for as long as its element stays connected to the DOM. `isStale` no longer invalidates refs wholesale — it only forces the liveness probe.
11. **Settle policy is set on `ctx.pendingSettle` by the action-tool wrapper and consumed by the first `execOnLeasedTab` call.** Internal multi-hop handlers do NOT pay the settle cost on every hop — `execOnLeasedTab` clears `pendingSettle` after the first injection.
12. **Cookie-banner subtrees collapse to a single placeholder node in the pruner.** The agent can still dismiss the banner by targeting the placeholder's ref; they just don't have to enumerate the banner's 30 internal buttons.
13. **Deleted — the full-mode floor (`meta.limit_adjusted`) is removed.** Full mode at a low limit now runs the same loud deterministic cap ladder as any other snapshot (#41); the old silent limit bump contradicted "the caller's limit is the caller's limit". (Numbering is append-only, so the slot stays.)
14. **`browser_evaluate` returning a primitive (string/number/boolean) is wrapped under `result`** in the response envelope, not spread. Spreading a string produces a char-indexed object (Issue #2 root cause); the wrapper detects primitives and arrays explicitly.
15. **MCP host runtimes stringify typed params on the wire** — `tabId=1594871391` arrives as `"1594871391"`, `force=true` as `"true"`, `methodIn=["POST"]` as `'["POST"]'`. Every numeric/boolean/array schema param goes through coercion (see Conventions). `z.coerce.boolean()` is unusable because it truthy-coerces any non-empty string; use `z.preprocess(coerceBoolean, z.boolean())` instead, and let empty strings fall through so the wrapping `.default(...)` still applies.
16. **Strict-CSP sites require `chrome.debugger Runtime.evaluate`, not `new Function()` in an injected script.** Sites like Suno, ChatGPT, GitHub, and banks set `script-src` without `'unsafe-eval'`, so any in-page evaluation of a string-as-JS via `chrome.scripting.executeScript` + `new Function(...)` is rejected. `browser_wait_for condition` mode is intercepted in `background.js::dispatchInner` and routed through `chrome.debugger Runtime.evaluate` (which runs as the debugger and bypasses CSP). The debugger is attached ONCE around the whole poll loop so the "started debugging this browser" infobar matches the wait duration.
17. **Image annotation runs in the extension's privileged context (OffscreenCanvas in the service worker), never in injected page scripts.** This sidesteps CSP entirely and keeps the annotation contract independent of page-side `script-src` restrictions. The `annotate_image` ExtCommand is stateless — bridge sends bitmap + rects + visual constants, extension returns the overlaid PNG/JPEG. Rects travel in CSS-pixel coordinates; the extension scales them to canvas pixels via `imgW / cssViewport.w` (no DPR involved — see invariant #25).
18. **Visual constants (badge color, font, sizing) live ONE-WAY on the bridge in `src/bridge/tools/visual.ts` and travel inside the `annotate_image` ExtCommand payload.** The extension is a dumb renderer — visual tweaks do NOT require an extension reload. Adding a new badge property means updating `VISUAL_CONSTANTS`, the `annotate_image` payload type in `protocol.ts`, and the extension's annotate handler in lockstep.
19. **Mixed-content envelope ordering: image content block at index 0, text at index 1.** Anthropic vision attends to images that precede related text. The text payload NEVER contains `dataBase64` — the bytes live exclusively in the image block. `toolResult` in `bridge/registry.ts` enforces both rules; `runUnifiedCapture` is the only caller that passes a non-undefined `image` argument.
20. **Standard mode keeps FACTS in DOCUMENT ORDER; nothing is ranked, scored, or silently dropped; every cap is loud.** The keep-rules admit everything interactive/navigational/data-bearing, table structure (`table`/`grid`/`treegrid` + cell roles — kept even unnamed so collapsed-row `values:` stay positionally aligned with the header row), PLUS any NAMED node — including named landmarks/containers (`region`/`main`/`navigation`/`list`/`group` carrying an aria-label). Only UNNAMED structural nodes stay out of `standard` (that's what `detail:"full"` is for). There is NO salience scoring anywhere in the pipeline — the old `scoreCandidate` ranking, sibling/off-axis/form/modal penalties, and reserved slots are deleted; kept nodes appear in DFS preorder (document order), the tree is then losslessly distilled (#38), and any reduction goes through the deterministic cap ladder (#41). **The walk spans the whole reachable page, not just the top document** (`HELPERS_VERSION` 9): `helpers.js::walkA11y` descends OPEN shadow roots (same coordinate space) and SAME-ORIGIN child frames (rects offset-accumulated to top-viewport at each frame boundary), so web components (UI5 buttons) and same-origin iframe apps (Storyline courseware) earn real refs in the single main-frame `WeakMap` — refs stay bare numeric and globally unique (no per-frame namespace; that's Phase 4 / cross-origin only). A CROSS-ORIGIN child frame can't be DOM-traversed from the main realm → by default it becomes a single named `iframe` leaf carrying `crossOrigin:true`, which the serializer renders with a loud `[cross-origin frame — not descended]` marker; `payload.meta.frames` (sourced from the raw tree root, which `helpers.js` stamps during the walk — no extra round trip) lists every child frame and whether it was `descended`. **Phase 4b — opt-in cross-origin descent (`includeCrossOriginFrames:true`):** the snapshot then `executeScript`s `walkA11y` into each cross-origin leaf's OWN realm (`chrome.scripting.executeScript({frameIds})` reaches OOPIFs under `<all_urls>`; live-validated against SANS `cc.sans.org` SCORM), and `descendCrossOriginFrames` (background.js) splices the returned subtree in under the leaf with `fN:localId` refs (frame-qualified, since per-frame `WeakMap`s would collide in the bare-numeric namespace — see #37's ref grammar via `src/snapshot/ref.ts`), offsetting child rects by the leaf's own top-viewport rect and clearing `crossOrigin` in favour of `frameDescended` (serializer renders `[cross-origin frame — descended]`). Action tools targeting an `fN:` ref route into the owning frame via `routeFrameAction`/`parseFrameRef`, rewriting `ref`/`targetRef` to the bare local id before `executeScript({frameIds})`; a trusted click resolves the spliced cross-origin rect → viewport coordinate. Descent is opt-in (extra injection + privacy/cost) and replayed on auto-snapshots (#8) until flipped off; an `executeScript` failure on a frame is non-fatal — that leaf degrades back to the not-descended marker. **Active-layer honesty:** an interactive node that is NOT the topmost `elementFromPoint` hit at its own centre is flagged `occluded` (a ghost under-layer control, e.g. a stale Storyline slide kept mounted) — a pure FACT rendered as `[occluded]` in the outline (#30) and diff-tracked (#31); it never affects inclusion or position. Old harness fixtures (captured pre-v9) carry none of these flags; the spliced-shape regression guard is the `frames-shadow` fixture. `viewportOnly` defaults to `false`, so the tree spans the WHOLE page (default `limit` is **1500** — the compact outline funds the larger tree). Reductions happen ONLY via the cap ladder (#41), and every reduction is LOUD: viewport fallback and the prefix cut each write `meta.notice` (a one-line recovery hint naming the exact levers — raise `limit`, `scope:"<ref>"`, `viewportOnly:true`, `save_tree_to_path:true`) which the serializer inlines as the outline's `NOTE:` first line (#30). `meta.total_candidates` is ALWAYS surfaced (the full page's post-distillation node count, pre-cap) so the agent can detect reduced-content situations. Explicit `viewportOnly:true` filters but never surfaces `viewport_fallback` (the caller already asked for it).
21. **`format` is not an agent-facing parameter — it is inferred from `save_to_path`'s file extension.** `.png` → PNG, `.jpg`/`.jpeg` → JPEG. For `save_to_path:false`/`undefined` (inline only) and `save_to_path:true` (auto-named `.jpg`), format defaults to JPEG. Unknown extensions on string paths are rejected at schema-validation time via `saveToPathSchema.refine(...)`. The single source of truth is `src/bridge/tools/save.ts::resolveSavePath`, which returns `{path, format}` and is called once up-front in `runUnifiedCapture`; the resolved format flows into both the `snapshot_capture` and `annotate_image` extension hops.
22. **Annotated screenshots suppress parent-rect strokes via containment.** `src/bridge/tools/containment.ts::computeDrawStroke` runs over the rect list before the `annotate_image` hop: any rect that strictly contains another annotated rect gets `drawStroke:false`. The extension always draws the badge (so the agent can still target the parent) but skips the stroke. Kills the "WebArea root strokes the entire viewport" visual noise. O(n²) with early break, sub-ms at typical n≤500. The `drawStroke` field is part of the `annotate_image.rects` ExtCommand contract (`protocol.ts`).
23. **Extension HUD (`indicator.js` pill + glow) is hidden during screenshot capture via a `data-browser-capturing="1"` attribute on `<html>`.** `background.js::doSnapshotCapture` calls `setCaptureAttribute(tabId, true)` before the capture hop and clears it in a `finally` block so the attribute never gets stuck on. The CSS rules in `inject/indicator.js::SHADOW_CSS` use `:host-context([data-browser-capturing="1"])` to hide the HUD reliably across the closed Shadow root. **DO NOT add an rAF-based paint wait** — agent tabs are background by default and Chrome throttles `requestAnimationFrame` to ~0 fps in background tabs; `Page.captureScreenshot` triggers its own paint pass which picks up the style invalidation. If a discrete delay is genuinely needed, use `setTimeout` (bounded), never rAF. (Background-tab rAF throttling can be lifted when `browser_activate_tab(level:"render")` focus-emulation is active — invariant #27 — but the capture path NEVER assumes emulation, so the rAF-free reasoning holds universally.)
24. **Chrome tab-group title is host-brandable via `BROWSER_EXTENSION_TAB_GROUP_LABEL` (default `"Automation"`).** The daemon reads the env var once at startup and stamps `tabGroupBrand` onto every `IndicatorState` before sending to the extension. The extension's `updateTabGroup` uses `state.tabGroupBrand ?? "Automation"` for the group title (e.g. `"Acme — Alice"`). This is the single permitted host-specific knob; everything else (extension display name, in-page pill text, log prefixes, internal globals) stays generic so the same MCP bundle is shippable standalone. Adding new host-brandable surfaces must follow the same shape: daemon-stamped on `IndicatorState`, extension-side default to the generic value when unset.
25. **Annotation scale is derived from final canvas dimensions vs. CSS viewport, not from DPR.** The formula is `scaleX = bmp.width / cssViewport.w` (and `scaleY = bmp.height / cssViewport.h`) where `bmp.width`/`bmp.height` are the post-resize canvas dimensions. DPR is NOT used in the math because it's baked into both quantities identically — the post-resize bitmap is `css × dpr × resizeRatio` pixels wide, and `cssViewport.w` is `css` pixels — so DPR drops out. This formula is invariant to which hop did the resize (hop 1 pre-resize or hop 2 re-resize, single or double). Earlier rounds used `scale = dpr * resizeRatio` which broke when hop 1 pre-resized to `maxWidth`: hop 2's `if (bmp.width > maxWidth)` guard was then false, the resize factor was silently dropped, and rect coords drifted in proportion to (CSS distance × (1 - DPR)). `cssViewport` is surfaced by `helpers.js::__mcpA11y` as `root.cssViewport = {w: window.innerWidth, h: window.innerHeight}`, forwarded through `snapshot_capture`'s response and into the `annotate_image` ExtCommand payload.
26. **`browser_snapshot.screenshot` is a tri-state enum — never a boolean.** Values: `"off"` (default; tree only, no image), `"annotated"` (tree + image with red ref badges painted on each rect; the vision-ready output), `"raw"` (tree + clean pixels with no badges; for saving artifacts or showing the page as the user sees it). The annotate-hop gate is `screenshot === "annotated"` — NOT `screenshot && refs > 0` — so `"raw"` returns the captured bytes untouched even when refs exist. Round 10 promotion from boolean (the former standalone `browser_screenshot` tool was removed in favour of `screenshot:"raw"`). Auto-snapshot replay (invariant #8) propagates the enum verbatim, so an agent that picks `"annotated"` or `"raw"` keeps getting the same flavour of image per action until it flips back to `"off"`.
27. **`browser_activate_tab(level:"render")` (focus-emulation) is a RENDERING/visibility aid, NOT an input precondition.** It issues CDP `Emulation.setFocusEmulationEnabled{true}` + `Page.setWebLifecycleState{active}` so a backgrounded canvas SPA renders as if visible+focused — screenshots and on-screen selection/scroll/menu rendering become faithful. It does NOT gate input: synthetic DOM events and ordinary actions reach the page's JS model regardless of emulation (proven on Google Sheets — synthetic nav+paste commits identically whether the tab is 0fps-throttled or emulation-on). Lifetime is opt-in / per-need (default OFF), tracked SW-side in the `focusEmulated` Set (NOT debugger state, so it survives a detach). `debuggerAttach` re-asserts emulation on every fresh attach for flagged tabs, so rAF stays live across any attach/detach churn; on a leased tab the debugger session is lease-owned (#42) — held until release, with `DETACH_IDLE_MS` demoted to an orphan-only net — so emulation stays live without churn. An extension reload wipes the `focusEmulated` Set — re-call `browser_activate_tab(level:"render")` after any reload. Side effect: because each enable + re-assert toggles the page's visibility/focus state, visibility/focus-gated page logic (analytics beacons, ad-refresh, autoplay-resume) may fire repeatedly while emulation is held.
28. **Disabling focus-emulation (`browser_activate_tab(level:"background")`) detaches the debugger PROMPTLY to revert all session-scoped CDP overrides atomically.** `setFocusEmulation(tabId,false)` clears the `focusEmulated` flag, issues `setFocusEmulationEnabled{false}`, then calls `debuggerDetachNow` (cancel any pending deferred-detach timer + `chrome.debugger.detach`). Detaching is the only way to clear the lingering `Page.setWebLifecycleState{active}` override in one step — CDP exposes only `active`/`frozen` lifecycle states, neither of which is the natural background state, so a prompt detach (NOT a `frozen` override, NOT the long idle backstop used on the enable path) is the correct clean revert. After disable the tab returns straight to Chrome's natural background throttling (verified: rAF 0fps / `visibilityState:"hidden"` / `hasFocus:false`). On a LEASED tab, `setFocusEmulation(false)` immediately RE-attaches via `leaseAttach` after the detach — the detach is the atomic override-revert mechanism, not a surrender of the lease-owned session (#36/#42); the fresh attach re-asserts nothing (the `focusEmulated` flag is already cleared), so the tab stays throttled while the lease keeps its debugger.
29. **`browser_activate_tab(level:"foreground")` is the SOLE sanctioned focus-theft.** It is the only code path that calls `chrome.windows.update({focused:true})`, and the only ACQUISITIVE `chrome.tabs.update({active:true})` (invariants #1/#2 carve it out by name; the popup net's activation, #46, is restorative — it puts focus back, never takes it; it routes to the `bringToFront` handler in `background.js`). It genuinely raises the window and activates the tab — reserve it for focus-dependent flows that focus-emulation cannot satisfy: OS file pickers, clipboard-paste permission prompts, drag-and-drop, native `:focus`-gated UI. It captures `previousActiveTab` first so the caller can restore the user's prior tab, and requires a lease on the target (returns `lease_required` otherwise). For canvas/rendering needs use `level:"render"` (#27) — no focus theft. Verified live: with a non-Chrome app foregrounded, `level:"render"` left the OS foreground unchanged, whereas `level:"foreground"` raised Chrome.
30. **The snapshot tree ships as a compact indented-text outline (a STRING), not nested JSON.** `bridge/tools/capture.ts` serializes the pruned tree through `snapshot/serialize.ts::serializeTree` into one line per node — `{2-space-indent}- {role}[ "{name}"][ [ref={ref}]][ = "{value}"][ flags…][ values: …][ (showing X of Y rows)]`, flag order checked/mixed → selected → disabled → occluded → level. A collapsed table row (#40) renders `values: "a", "b", ""` — one slot per cell in header order, empty cells holding their `""` slot so values align positionally with the header row's values; a partially-shown table's element gets `(showing X of Y rows)` appended. The synthetic root ("0") prints no `[ref]` tag (mirrors populateRefs, which never registers "0"); names/values are whitespace-collapsed with embedded `"` escaped. The outline lands in `payload.tree`; the structured pruner `meta` (counts/fallbacks) is split out to `payload.meta`. The MCP transport envelope stays JSON — action results nest the snapshot under `payload.snapshot` and the image-bearing envelope's capture-result duck-type (#19) requires an object payload — so only the TREE representation is text, never the envelope. The pruner's recovery `meta.notice` (set on any cap/fallback) is inlined as the outline's first line, prefixed `NOTE: `, so it can't be missed while staying machine-readable in `payload.meta`. The single-source node-line grammar lives in `serialize.ts::formatNodeFields` (shared by the full-tree serializer and the diff serializer, #31); the `serialize.test.mjs` suite pins it (shape AND content).
31. **Auto-snapshots diff; explicit snapshots are full.** An action tool's auto-snapshot (the `replaySnapshot` path, which passes `allowDiff:true`) returns only what changed since the previous snapshot of that tab — `snapshot/diff.ts::serializeDiff` flattens the prior and new pruned trees by the stable+non-evicting ref (#10), classifies each ref added / removed / changed, and renders the CP3 node-line grammar with `+`/`-`/`~` markers under a `Δ {A} added, {R} removed, {K} changed` header (`Δ no changes` when nothing moved). `~` lines carry the identity lead plus `field: old → new` transitions. `browser_snapshot` leaves `allowDiff` false and ALWAYS returns the full outline. `~` transitions include `occluded: false → true` (a layer slid over the element — boolean-normalized so absent ≡ false); `rowsShown` is deliberately NOT diff-tracked (a count delta is churn, not a page change). The diff is per-tab: the prior tree lives in `session.lastPrunedTree`/`lastPrunedTreeTabId`, refreshed on EVERY snapshot (explicit or auto) EXCEPT a scoped one — a `scope:"<ref>"` snapshot never disturbs the diff baseline (#39), so the next action's diff still reflects the whole page. Each action's diff reflects only that action's delta; a cross-tab prior (page-side ref ids are per-tab) or a missing prior forces full. `runUnifiedCapture` also falls back to full whenever the diff string would be ≥ the full outline (full-page navigation turns over every ref) — a diff is never larger than just showing the tree. `payload.meta.mode` (`"diff"`|`"full"`) records which was returned; it is set by the capture orchestrator, never by `prune()` (which always produces a full tree). The diff serializes a STRING into `payload.tree` like the full outline (#30) — the transport envelope stays JSON.
32. **`browser_resize` overrides the viewport via debugger-scoped CDP `Emulation.setDeviceMetricsOverride`, sticky per-tab and re-asserted on every fresh attach — never a window raise.** `background.js::setResize` stores `{width,height}` in the `deviceMetrics` Map (SW state, NOT debugger state, mirroring `focusEmulated` / invariant #27) and calls `Emulation.setDeviceMetricsOverride{width,height,deviceScaleFactor:0,mobile:false}` (DSF 0 = host-natural DPR — a pure viewport resize, not device emulation). Because the override is debugger-session-scoped (clears on detach), `debuggerAttach` re-asserts it (via `assertDeviceMetrics`) on every fresh attach for tabs in the map — sharing the SAME re-assert hook as focus-emulation, so an action sequence keeps the resized viewport across the attach/detach churn. It clears on tab-close (`onRemoved` deletes the map entry) or extension reload; disabling focus-emulation (`debuggerDetachNow`, invariant #28) transiently drops it until the next attach re-asserts. Resize is NOT in `ACTION_KINDS`/`SETTLE_KINDS` (it's an environment override, not a page mutation — like `set_focus_emulation`/`bring_to_front`); it never raises the window, keeping invariants #1/#2 intact.
33. **`browser_fill_form` is pure bridge-side batching over the existing `type`/`select_option`/`click` ExtCommands — no new page-side handler, no `HELPERS_VERSION` bump.** The tool sequences existing single-field actions over a `{ref, value, kind?}[]` array (kind defaults to `"type"`), so it needs NO extension reload to ship. It clears `ctx.pendingSettle` up-front so fields fire back-to-back with no inter-field settle; the single auto-snapshot after the batch (the `registerActionTool` wrapper) covers the final repaint. A `"type"`/`"select_option"` field missing `value` is rejected before any hop. Never refactor this into a page-side batch handler — the no-reload property is the point.
34. **`browser_drag`/`browser_drop` are page-side synthetic events — no CDP `Input.*`, no window raise.** `helpers.js::actDrag`/`actDrop` (new act kinds at `HELPERS_VERSION` 8 — they change the in-page contract, so adding them bumps the version and forces an extension reload) dispatch the events directly in the page, mirroring `actClick`/`actHover`/`actUpload`. Synthetic page-side events remain the DEFAULT for every ordinary interaction; CDP `Input.*` is reserved for the explicit trusted-input escalation (#37) — `browser_drag`/`browser_drop` deliberately stay synthetic (a draggable/file-drop flow rarely gates on trust, and the synthetic path needs no debugger attach). `browser_drag` carries two mechanisms: **"native"** fires the HTML5 DnD-API sequence (`dragstart`→`dragenter`→`dragover`→`drop`→`dragend` with one shared `DataTransfer`) for `draggable="true"` sources; **"pointer"** fires a `mousedown`→interpolated-`mousemove`→`mouseup` sequence (paired `PointerEvent`s) for pointer-based DnD libraries (SortableJS forceFallback, react-beautiful-dnd, kanban boards) — the two event families are mutually exclusive in what they drive, so **"auto"** (default) picks native when the source's `draggable` flag is set and pointer otherwise. Synthetic events are `isTrusted:false`, so the rare library that gates on trust won't react (the documented escape hatch is `browser_activate_tab(level:"foreground")` for native-only flows). `browser_drop` is file-drop only: it reuses the `upload` command's base64 file-payload shape (`readUploadPayloads`) and synthesizes `dragenter`→`dragover`→`drop` carrying the files in a `DataTransfer`, so a "drag files here" zone with no `<input type=file>` is still reachable. Both kinds are settle-and-action kinds (in `ACTION_KINDS`/`SETTLE_KINDS` page-side and `SETTLEABLE_KINDS` bridge-side). `browser_drag`'s source ref rides the standard `execOnLeasedTab` ref-validation + liveness probe (#10); the target ref is validated bridge-side in the handler via `resolveRef` so a typo errors with nearby refs rather than a buried page-side "not found".
35. **No tool can block on a native JS dialog — `Page.*` is enabled on every debugger-attached tab and the global listener safe-defaults to DISMISS.** Native dialogs (`alert`/`confirm`/`prompt`/`beforeunload`) block the page until answered, and Chrome does NOT apply background-tab auto-dismiss while the debugger is attached — so any tab the agent reaches via the debugger (focus-emulation, viewport override, screenshot, `evaluate`, `wait_for`, dialog arming) would wedge on an unhandled `confirm()` for 30 s until the daemon timeout fires. Fix: `debuggerAttach` asserts `Page.enable` UNCONDITIONALLY on every fresh attach (alongside focus-emulation + viewport re-asserts), and a global `chrome.debugger.onEvent` listener (registered once at SW load) catches every `Page.javascriptDialogOpening`. Behaviour: an entry in `dialogDispositions: Map<tabId, {disposition, promptText?, lifetime}>` (the same SW-state-not-debugger-state model as `focusEmulated`/`deviceMetrics`) decides accept vs dismiss + `promptText`; with no entry, the TYPE-AWARE safe-default answers: `alert`/`confirm`/`prompt` are DISMISSED, `beforeunload` is ACCEPTED — but only while the agent is driving the tab (`isAgentDriving`: an in-flight command or within `BEFOREUNLOAD_GRACE_MS` of one), so the agent's own navigation proceeds while the USER's manual close of an idle leased tab keeps its unsaved-changes protection. EVERY auto-answer (armed or safe-default) is reported as a `{kind:"dialog", type, message?, disposition, wasArmed}` env event on the tab's ring (#43) — a dialog is never answered silently. `browser_handle_dialog` is the pre-arm interface — the agent calls it with `{disposition, promptText?, lifetime?}` BEFORE the action that triggers a dialog (typically right before a `browser_click` on a button known to fire a `confirm()`). `lifetime` defaults to `"one_shot"` (entry removed after the next dialog fires); `"sticky"` persists until an explicit `clear:true`. The disposition + lifetime travel in the wire ExtCommand `{kind:"handle_dialog", disposition?, promptText?, lifetime?, clear?}`; the tool layer enforces xor (exactly one of `disposition` / `clear:true`) before any daemon hop. Placed in `tabs.ts` via `registerTool` (NOT `registerActionTool` — arming a handler doesn't mutate the DOM, no auto-snapshot, no settle). Detach lifecycle is no longer per-lifetime: on a leased tab the debugger session is lease-owned (#42), so both `one_shot` and `sticky` arms ride the standing attach and page-driven dialogs (timers, network responses, `beforeunload`) always hit a live listener. **Defense-in-depth backup**: `inferExtTimeout` (`src/daemon/timeouts.ts`) tightens the synthetic-event action kinds (`click`/`type`/`hover`/`scroll`/`press_key`/`select_option`/`drag`/`drop`/`resolve_ref`) from the 30 s default to 10 s, so even in the rare event a dialog slips past the safe-default the agent waits 10 s for the action to give up, not 30 s.
36. **The debugger session is lease-owned end-to-end: the LEASE attaches it, the RELEASE detaches it.** `applyIndicatorState`'s `leased` edge fires `leaseAttach(tabId)` EAGERLY at claim time (fail-soft — an attach failure becomes the `attachBlocked` standing state, #48, never a blocked claim), so Chrome's "started debugging this browser" infobar appears once at claim and stays steady for the whole lease (the old model attached on first debugger-backed tool and, before that, per-action). Release triggers: (a) **clean lease release** — `applyIndicatorState` fires `debuggerDetachNow(tabId)` on the `released` indicator edge (`browser_release_tab` / release-all / bridge-disconnect), clearing the infobar at once (the `released` branch also clears the tab's env state, #43); (b) **tab close** — `chrome.tabs.onRemoved` clears the in-memory state (Chrome auto-detaches itself); (c) **orphan net** — `DETACH_IDLE_MS` (180 s, armed by `armOrphanDetach`) now exists ONLY for orphaned attachments on non-leased tabs and for stale leases after daemon death (the WS `close` handler arms it for every attached tab; a reconnect's indicator rebroadcast cancels it via `leaseAttach`). Mid-lease resilience is #42's job. All debugger state (`attached`, `attachPromises`, `detachTimers`, `focusEmulated`, `deviceMetrics`, `dialogDispositions`) is keyed by tabId and the daemon's lease layer guarantees one agent per tab, so holding longer changes DURATION, not concurrency; a force-revoke handover emits leased→leased (never `released`), so the debugger correctly stays attached as the tab passes between agents.
37. **Trusted coordinate/key input is a CDP `Input.*` escalation over the synthetic default — opt-in, never the default path.** Page-side synthetic events (#34) reach the page's JS model for almost everything without a debugger attach. The exceptions are widgets that gate on `event.isTrusted` (custom switches, signature-pad canvases, some media players) and interactions with no usable ref (a coordinate inside a cross-origin iframe, a `<canvas>` hit-region). For those, `browser_click_xy`, `browser_draw`, and the `trusted:true` flags on `browser_click`/`browser_press_key`/`browser_type` dispatch REAL browser input via CDP `Input.dispatchMouseEvent`/`dispatchKeyEvent`/`insertText` (extension-side: `dispatchTrustedClick`/`dispatchTrustedStroke`/`dispatchTrustedKey`/`dispatchTrustedType`). Costs over synthetic: (a) the "started debugging this browser" infobar (the debugger is attached and held for the lease, same as focus-emulation — #36); (b) real handlers fire and coordinates hit-test through overlays, so a wrong coordinate clicks whatever is actually under the point (no ref safety net); (c) coordinates are CSS-pixel **viewport** coords (top-left origin, pre-scroll) in the same space as snapshot rects — `browser_click(ref, trusted:true)` resolves the ref's snapshot-time rect centre bridge-side (and runs the same `resolve_ref` liveness probe as the synthetic path so a since-removed element errors instead of clicking empty space — but uses the SNAPSHOT rect for the coordinate, since `resolve_ref` returns a frame-local rect that would be wrong for a same-origin-iframe element; re-snapshot if the element may have moved), and `browser_click_xy`/`browser_draw` validate coords against the last-snapshot viewport (`session.lastViewport`) and error instructively on out-of-bounds. Each trusted dispatch **auto-asserts focus-emulation** first (`ensureFocusForTrustedInput` attaches + asserts + flags the tab in `focusEmulated`) so an occluded/backgrounded tab composites and hit-tests faithfully at the dispatched point — without raising the window. The trusted kinds are settle-and-action kinds (`click_xy`/`draw` in `ACTION_KINDS`/`SETTLE_KINDS` extension-side and `SETTLEABLE_KINDS`/`FAST_ACTION_KINDS` bridge/daemon-side); `press_key` was already in those sets and the `trusted` branch routes inside `dispatchInner`. Modifier names and mouse buttons map to CDP bitfields (`CDP_MODIFIER_BITS`/`CDP_BUTTON_BITS`); held modifiers are pressed as real keydowns before the main key so browser shortcuts (Ctrl+A, Shift+Tab) actually fire, and non-printable keys carry `windowsVirtualKeyCode` (`CDP_KEY_DEFS`) so the browser performs the key's default action (Enter submits, Tab moves focus). **`browser_type(trusted:true)`** extends the escalation to **controlled rich-text editors** (DraftJS/Slate — e.g. TikTok's DM composer) whose internal model updates ONLY on a real input event: the synthetic default (value-set / `execCommand insertText`) leaves the text in the DOM but not the editor's model, so its send affordance never arms and the text is inert (uneditable, unsendable). `dispatchTrustedType` focuses the ref's editable via a new `focus_ref` helper (selecting-all when `!append` so the insert replaces) then dispatches CDP `Input.insertText` — the one warranted use of a bulk trusted text insert over per-key `dispatchTrustedKey`. Adding `focus_ref` bumped `HELPERS_VERSION` (10→11), forcing an extension reload.
38. **Distillation is LOSSLESS — it may merge or unwrap, never delete a fact.** `snapshot/distill.ts::distill` runs bottom-up between collection and the cap ladder: it merges adjacent plain-text leaves (first fragment's ref survives), drops leaf text/wrappers that merely RESTATE their parent's name, drops nameless childless images/cells, and unwraps single-child unnamed fact-free wrappers (`generic`/`none`/`presentation` + cell roles; never the root). **Fact-immunity is the gate:** a node carrying any fact — `value`/`checked`/`selected`/`disabled`/`level`/`values`/`occluded`/`crossOrigin`/`frameDescended`, or an interactive/nav/data role — is untouchable. Distill is idempotent and non-mutating; a distilled tree re-distilled is byte-identical. Any future rule must preserve "every fact in the raw kept-set appears in the output exactly once".
39. **`scope` and `save_tree_to_path` are strictly per-call — structurally incapable of replay.** Neither field exists on `SnapshotParams` (`bridge/session.ts`), so `updateSnapshotParams` cannot persist them and `replaySnapshot` cannot replay them — the guarantee is enforced by the type shape, not by discipline. A scoped snapshot additionally skips the diff-baseline refresh (`session.lastPrunedTree`, #31), so a drill-down never poisons subsequent action diffs, and requires the last snapshot to be of the SAME tab (page-side ids are per-tab and collide across tabs — a cross-tab scope would silently return the wrong subtree, so it errors instead). `save_tree_to_path` writes the FULL uncapped outline (`limit: MAX_SAFE_INTEGER`, no viewport filter) to disk and merges its refs into `refRegistry` ONLY (never `lastSnapshotRefs`) — file-sourced refs are actable but never masquerade as "freshly seen this snapshot".
40. **Table rows collapse to `values:` only when EVERY cell is simple; the scope root never collapses.** A row collapses iff every kept child is a simple cell (cell role whose kept descendants are all plain text — no links, buttons, inputs, or nested structure); one interactive descendant keeps the whole row expanded so its refs stay targetable. Collapse maps each cell to its name (empty cell → `""` slot) preserving header-order alignment (#30), and drops a row name that merely restates its own cell values. The node a `scope` call roots at is never collapsed (`isRoot` guard) — scoping into a row must show its cells, or the drill-down lever (#41's recovery hint) would be self-defeating.
41. **Every reduction goes through ONE deterministic cap ladder — no ranking anywhere.** When the distilled tree exceeds `limit`: (1) retry scoped to the viewport — engaged only when the viewport subset is larger than the bare document root (`count > 1`) AND smaller than the full tree, surfaced as `meta.viewport_fallback {active, reason:"page_too_large", threshold, total_candidates}`; (2) if still over, cut at `limit` in DOCUMENT ORDER, surfaced as `meta.truncated {shown, total, first_omitted_ref}`. The document root ALWAYS survives the viewport gate — even scrolled out of view its page-side rect reads as off-viewport, but dropping it would degrade the tree into a rootless forest (losing the page title) and churn the action-diff with a phantom root removal on every scroll; so "empty viewport subset" means root-only, not literally zero. Both steps write `meta.notice` naming recovery levers, inlined as the outline's `NOTE:` first line — the prefix-cut notice names all four (raise `limit` / `scope:"<ref>"` / `viewportOnly:true` / `save_tree_to_path:true`); the viewport-fallback notice offers "scroll" in place of `viewportOnly:true` (the output is already viewport-scoped). Which nodes survive is a pure function of (tree, limit, viewport) — same inputs, same output, no scores, no tie-breaking heuristics. Partial tables under the cut carry `(showing X of Y rows)` (#30) so a truncated table is never mistaken for a complete one. The prefix-cut notice offers the `viewportOnly:true` lever ONLY when the cut tree is not already viewport-scoped (explicitly or via the fallback) — a dead lever is never suggested.
42. **Mid-lease attach resilience: concurrent attaches dedup, detaches are reason-aware, and re-attach is deliberate.** `debuggerAttach` keeps an `attachPromises: Map<tabId, Promise>` — every caller of an in-flight attach (eager `leaseAttach`, a command path, an onCommitted re-attach) shares ONE `chrome.debugger.attach`, so racing paths can't double-attach and manufacture spurious `attachBlocked` states. `chrome.debugger.onDetach` re-attaches a leased tab EXCEPT when (a) `reason === "canceled_by_user"` — the user clicked the infobar's Cancel, and fighting that would be an endless loop; the NEXT agent command re-attaches instead (intent, not reflex) — or (b) the daemon WS is not OPEN — stale `indicatorState` after daemon death must not re-acquire the debugger with the orphan net (#36c) disarmed. `webNavigation.onCommitted` (main frame) also re-attaches a leased-but-detached tab, and `dispatch()` fires a fire-and-forget `leaseAttach` retry when a standing `attachBlocked` exists, so recovery is continual but never a tight loop.
43. **Every tool response may carry a per-tab `environment` report — events report ONCE, standing states re-stamp until cleared, and env state dies with the lease era.** Extension-side, each tab has an EVENT RING (`envEvents`, capped `ENV_EVENTS_MAX=20` — auto-answered dialogs, popups) drained into the next response for that tab, and STANDING STATES (`envStanding` — `fileChooser` #45, `attachBlocked` #48) re-stamped on EVERY response until the condition clears. `handleMessage` stamps `env` on BOTH ok and error responses (single choke point); the daemon captures it per-tab (`envByTab`), consumes it once per bridge exec (NEVER for a `lease_required` error — env must not leak to a non-holder), and clears it on tab close/release/bridge-close; the bridge client accumulates per-tab (`pendingEnv` — events concat, standing replaced WHOLESALE by the newest response so cleared conditions actually clear), and the tool wrappers stamp `ctx.daemon.takeEnv()` (consume-once) as `environment` on success AND error envelopes — an `EnvReport` (single tabId-stamped object or array). Lean by construction: no env → no key. Lease release clears `envEvents`/`envStanding` extension-side and `envByTab` daemon-side — a new lease never inherits a prior agent's era. `browser_snapshot` additionally leads the outline with `NOTE:` lines for standing states (via `peekEnv`, which never consumes).
44. **Dialog auto-answers are never silent, and `beforeunload` acceptance is scoped to agent activity.** Covered in #35: the type-aware safe-default (dismiss `alert`/`confirm`/`prompt`; accept `beforeunload` only while `isAgentDriving`) and the mandatory `{kind:"dialog", …, wasArmed}` env event on every auto-answer, armed or not. An armed disposition (`browser_handle_dialog`) always wins over the safe-default and reports `wasArmed:true`. Live-verified: agent `browser_navigate` off a dirty page proceeds and reports; the message is clamped to `ENV_DIALOG_MESSAGE_MAX` (300).
45. **Native file choosers on a leased tab are INTERCEPTED, reported as a standing state, and fulfilled headlessly by targetless `browser_upload`.** `Page.setInterceptFileChooserDialog{enabled:true}` is asserted in `debuggerAttach`'s re-assert family, so a click that would open the OS picker instead fires `Page.fileChooserOpened` → standing `fileChooser {mode, backendNodeId?}` (#43) + a snapshot `NOTE:`. `browser_upload` with NEITHER `ref` NOR `selector` fulfils it via `DOM.setFileInputFiles` with LOCAL PATHS (no base64 round-trip, none of the payload ceilings; paths must be absolute — a relative path errors bridge-side BEFORE any hop, since it could only resolve against the bridge process's cwd). The standing state clears on fulfilment or main-frame navigation; a no-backendNodeId chooser (File System Access picker) and a fulfil-with-no-chooser both error honestly. Trade-offs (documented, accepted): while a tab is leased the USER's own manual uploads on it are intercepted too; and an OOPIF-originated chooser (file input inside a cross-origin iframe) is NOT intercepted — the OS picker opens natively (live-verified on mdnplay.dev frames) — so for OOPIF inputs target the element directly (`ref:"fN:…"`/`selector` upload works, live-verified).
46. **Popup focus-theft is reverted by a restorative net, and the popup is auto-leased.** A `tabs.onCreated` whose `openerTabId` is a LEASED tab and which arrived `active:true` stole focus the agent's trusted click (or page `window.open`) caused; the net re-activates the previously-active tab (`lastActiveByWindow` — Chrome fires `onActivated` AFTER `onCreated`, so `current` at onCreated time IS the restore target) — the second sanctioned `chrome.tabs.update({active:true})` (#1), restorative never acquisitive. The popup is reported as a `{kind:"popup", tabId, url, restoredFocus, leased}` env event on the OPENER's ring (`url` may be `""` — Chrome often has neither `url` nor `pendingUrl` at onCreated; resolve via `browser_list_tabs`), and an `ExtEvent popup_opened` lets the daemon auto-claim the popup's lease for the opener's session (+ indicator push → eager attach), so the popup is immediately controllable without a manual `browser_switch_tab`. Synthetic (untrusted) clicks on `_blank` anchors open nothing at all (popup blocker) — the net exists for the TRUSTED path. Known hole (documented): a popup opened into a NEW WINDOW can't be un-raised.
47. **The daemon keeps a liveness journal for connection-dropout forensics.** `liveness.jsonl` in the runtime dir (512 KB size-cap, rotate to `.1`) records `daemon_boot`, `ext_ws_open`/`ext_ws_close{code,reason}`/replaced/error, `ext_hello {version, swStartedAt}` (the extension announces itself on every WS open), `bridge_subscribe`/`bridge_close` (+ leases released), and per-command `ext_command_timeout`. The "extension not connected" error is enriched with the last disconnect's cause + age so an agent sees WHY (e.g. `code:1001` = extension reloaded) instead of a bare failure.
48. **A blocked debugger attach becomes a standing `attachBlocked` state naming the likely culprit — and `browser_evaluate` degrades to a MAIN-world fallback, never a dead end.** `leaseAttach` failure sets standing `attachBlocked {error, conflicting}` (#43), where `conflicting` lists foreign `chrome-extension://` frame origins from `webNavigation.getAllFrames` (the C1 signature: another extension's debugger/OOPIF holding the tab); it clears on the next successful attach, and recovery retries ride #42. While blocked, `runEvaluate` falls back to `chrome.scripting.executeScript world:"MAIN"` (indirect eval, awaits promises); if BOTH paths fail the error names both failures + the CSP caveat and suggests navigation/foreground recovery. There is deliberately NO `targetId` bypass of Chrome's one-debugger-per-target rule.

49. **`browser_fetch` is a lease-free privileged first-party request — no tab, no debugger.** Its wire command is a top-level `BridgeRequest` (`type:"fetch"`, no `tabId`), so it never leases a tab or attaches a debugger, and it therefore carries NO `environment` field (env-stamping flows only for `type:"exec"`). The MV3 service worker issues the `fetch` under `host_permissions:["<all_urls>"]`, making it first-party for the target origin: `credentials:"include"` attaches the user's real cookies (incl. httpOnly, SameSite=Lax/Strict) and the response is read CORS-exempt. `Set-Cookie` is NEVER exposed (the Fetch spec forbids it — read cookies via `browser_cookies`). Body size has TWO independent caps that map to TWO distinct flags: the SW cuts any body at a 25 MB hard ceiling → `truncated:true` (propagates via spread); when `save_to_path` is set the FULL body (up to that ceiling) is written to disk (`fetchedTo`) and the inline copy becomes a preview cut to `max_inline_bytes` → `previewTruncated:true`. The inline preview is always cut on a safe boundary — text via `trimLoneHighSurrogate`, base64 on a 4-char quantum — so it never carries a torn UTF-8 sequence or an undecodable base64 tail. A save-path failure is non-fatal (`fetchError`); the inline body still returns. Auto-named offload files use `.txt` for text bodies and `.bin` for binary.

50. **`browser_cookies` is lease-free and read-only — it reads the cookie jar, never writes it.** Wire command `type:"cookies"` (no `tabId`, no `environment`); requires at least one of `url`/`domain` (the handler rejects a bare call before any daemon hop) and optionally filters by `name`. It reads the default (non-incognito) store via `chrome.cookies.getAll`, returning httpOnly cookies that `document.cookie` (through `browser_evaluate`) cannot see. CHIPS partitioned cookies are deliberately NOT returned (the unpartitioned jar only — no `partitionKey` in the query). There is no cookie write/delete surface by design (a credential-vault feature is scoped out).

51. **`browser_open_tab` can target a window or an incognito window, and `browser_list_tabs` reports `incognito` per tab.** `windowId` routes the new tab into an existing window via `chrome.tabs.create({windowId})`; `incognito:true` opens it in an incognito window via `chrome.windows.create({incognito:true})`. Because the extension runs in spanning mode (no `"incognito"` manifest key), an incognito main frame it created cannot be scripted — on refusal the incognito branch removes the half-created window (no leak) and throws an honest error pointing at "Allow in Incognito". `TabInfo` carries an `incognito` boolean end-to-end so the agent can see which store a tab belongs to.
